## 1. 模块需求（五要素：目标 / 功能点 / 边界 / 验收 / 依赖）

### M1 进度安全：豆子补给与防卡死（P0）

- **目标**：任何存档、任何时刻，玩家都至少有一条零障碍的推进路径——"卡死"在机制上不可能。
- **功能点**：
  1. 豆子补给：门店内可花钱买豆（价格用 `bean.purchase_price`，每袋 = `bean_portions_per_bag` 份），
     入口与交互由设计定；必须保证"永远买得起最便宜的一支可出杯豆"（配合 M2 或最低价兜底）。
  2. 应急兜底：客人关在"无豆可出"时提供零成本应急出杯路径（如"店里常备的最后一小袋应急豆"），
     出杯流程与正常一致，**不改 story 内容**；保证任何状态下客人关可完成。
  3. 旧档自愈：已经卡死的旧档加载后立即获得可玩路径（不要求删档、不要求重置进度）。
  4. 全链路防卡死扫描：新增"贪心通关模拟"测试，50 关全程自动可通。
- **边界**：不改 story/** 与 content/**；应急兜底是游戏轨机制（UI 文案），不是剧情改写。
- **验收**（机检）：① 模拟测试：从新档开始，50 关全程可通关（含全部 11 个客人关）；
  ② 构造"0 豆 + 0 现金"存档进入客人关 → 可完成；③ 现有测试全绿。
- **依赖**：`state.ts` 库存/效果函数、`App.tsx` 出杯链路、content 豆数据（`purchase_price` 已有）。

### M2 经济放宽：金钱无限（开关，默认开）

- **目标**：体验期去掉经济摩擦，让玩家专注内容；随时可切回真实经济。
- **功能点**：
  1. "宽松模式"开关（金钱无限）：默认**开启**；状态持久化（建议与存档解耦的全局设置，旧档自动生效）。
  2. 开启时：买豆/升级/选项扣费永不失败；HUD 现金位显示 ∞；日结算流水照常记录。
  3. 关闭后立即恢复真实经济（余额为非负合理值；建议口径：开启期间消费免扣、进账照记）。
  4. 现有测试口径不变（money 起步 3000）。
- **边界**：不改 `contracts/state-keys.json` 数值边界；不删经济算法（关闭后完整可用）。
- **验收**（机检）：① 开启时买豆/升级/扣费后 money 不受损；② 关闭后扣减与进账恢复且数值正确；③ 测试全绿。
- **依赖**：M1（买豆入口）、M5（设置持久化路径）。

### M3 无尽营业：通关后「自由营业」日循环

- **目标**：走完 50 关后游戏不结束——每天开门营业、接单出杯、积累口碑与熟客，不设终点。
- **功能点**：
  1. 触发：第五章完成（`current_stage` 为空且 50 关完成）→ 首页出现「开门营业」入口，进入自由营业循环；
     不再出现"等新章节"的死文案。
  2. 每日循环：按精力（复用 energy 字段）接待有限客人；客人从**非玩家 6 位**角色池随机
     （7 位角色里除去 `player`，那是玩家自己，见 `story/characters.json`）；订单 = 饮品 + 风味偏好
     （由豆/饮品数据生成，如"想喝低酸顺口的"）。
  3. 每单三段判定：①饮品对不对 ②豆选得准不准（风味标签匹配）③手法（M8 交互质量）→ 星级（1~3 星）+
     相应收入/满意度/口碑变化；判定给一句数据依据（如"这支豆的 flavor_tags 命中'低酸'"）。
  4. 成长轴（不新增剧情文本，全部由现有数据驱动）：口碑影响客流与难度；熟客（trust 按角色）积累；
     豆种图鉴与配方图鉴（配合 M7）。
  5. 日终沿用现有结算页结构，加"营业第 N 天"标识。
  6. 失败软处理：没满足只是少星少收，无硬失败、不可卡死；豆/钱经 M1 机制永远可得。
- **边界**：不新增剧情/对白文本（订单与反馈文案由模板+数据生成）；不改 story 50 关；不消耗主线进度。
- **验收**（机检）：① 通关档进入自由营业，模拟连跑 ≥10 日无异常、无卡死、数值均在界限内；
  ② 订单生成器对角色 × 饮品组合均产出合法订单。手工：出单→出杯→星级→日结算一轮。
- **依赖**：M1（资源）、M2（经济口径）、M8（手法判定）、content 豆标签数据。
- **形态说明**：日循环是"更优模式"研究的推荐结论；备选与其他模式见提案档。

### M4 手机版：移动适配 + PWA 可安装 + 部署核对

- **目标**：手机上浏览器打开即玩，可"添加到主屏幕"像 App 一样启动；离线壳可打开。
- **功能点**：
  1. 响应式走查与补齐：360~430px 宽度逐屏检查（首页/店内/关卡/出杯/结算/无尽），无横向滚动、
     触控目标 ≥44px（已有基础样式：`game/src/styles.css:801` 起）、底部安全区适配。
  2. PWA：manifest（名称/图标/主题色/standalone）+ service worker（版本化缓存、离线开壳）+
     apple-touch-icon 与 iOS meta（180px PNG 图标）。
  3. 图标：用现有素材转换或零依赖生成；产物入库。
  4. 部署核对：vite `base:'./'` + Pages workflow；构建产物含全部 PWA 文件；缓存更新策略（新版本自动提示）。
- **边界**：不做原生壳（apk/ipa）；不做账号/云同步；默认沿用现有 github.io 地址（自定义域名另行决策）；
  如确需新增 `public/` 目录放置 PWA 静态文件，在设计文档中列明（见 X1）。
- **验收**：机检——build 产物含 manifest/sw/icons、validate/test 全绿；手工（用户侧）——手机浏览器打开→
  开局→出杯→结算→添加到主屏幕。
- **依赖**：M8（触控）、现有部署 workflow。

### M5 存档：一人一档（已具备）＋跨设备迁移＋完成态显示修复

- **目标**：进度可以跟人走——桌面玩到一半，导出到手机继续玩。
- **功能点**：
  1. 导出：任一档位导出一段"存档码"（文本，含版本与校验），可复制 / 系统分享 / 下载文件。
  2. 导入：粘贴存档码 → 校验（版本/校验和/结构）→ 生成**新档位**（不覆盖现有档）；非法码明确报错。
  3. 修复完成态显示："第章" → 按进度显示（如"已通关 · 自由营业中"）。
- **边界**：不做云同步/账号；存档码 = 编码包络 + 存档 JSON + **营业档案（可选字段）**——
  存档结构与 `contracts/**` 保持兼容、一字不改（营业档案是本机侧车数据，不是 `PlayerSave` 字段）；
  旧码或缺失营业档案的码导入时优雅降级：营业档案从「营业第 1 天」新建，不报错、不阻断导入。
- **验收**（机检）：① 导出→导入 round-trip 存档深等；② 非法/篡改码被拒绝；③ 完成态文案断言；
  ④ 载荷含营业档案的 round-trip 深等；⑤ 缺营业档案字段的码 → 导入成功且营业天数从 1 起。
  手工：真机双端走一遍（桌面导出 → 手机导入继续）。
- **依赖**：`state.ts` 档位函数；M4（手机侧）。

### M6 问题反馈窗口（零后端）

- **目标**：任何界面出问题，玩家能一键把现场信息交给店主（复制文本发微信即可）。
- **功能点**：
  1. 全局入口（任意界面 ≤2 次点击可达）：面板含类型（bug/卡住/建议）+ 描述输入。
  2. 自动环境快照：版本、当前档位与进度（章节/关卡/已完成数）、现金与豆库存摘要、最近操作
     （内存环形缓冲，约 20~30 条）、最近一次报错（若有）、UA/屏幕/语言/时间。
  3. 生成结构化文本（人读段 + JSON 段），一键复制 / Web Share / 下载 .txt；本机"我的反馈"列表
     （最近若干条，可再复制）。
  4. 全局错误捕获：未捕获异常与 Promise 异常进入快照。
  5. 直连上报通道仅留扩展点，不实现传输。
- **边界**：不做服务端收集、不自动上传（隐私）、不做账号。
- **验收**（机检）：① 快照含全部必需字段；② 环形缓冲顺序正确；③ 错误捕获注入测试。
  手工：复制/分享可用。
- **依赖**：无（纯前端）。

### M7 配方共创：做法提交与收录

- **目标**：玩家（含店主）把"我的咖啡做法"提交进游戏，形成可积累、可传播的配方库。
- **功能点**：
  1. 配方编辑器：名称、署名、豆（指定或"任意"）、饮品类型、参数（按 method：粉量/水量/水温/研磨/时长等）、
     风味笔记；"刚从吧台做的那杯"一键存为配方草稿（联动 M8）。
  2. 提交码：配方序列化为一段可复制文本（版本+校验），可分享给店主/朋友。
  3. 收录台（店主视角）：粘贴提交码 → 校验 → 预览 → 收录入本机配方库；重复码去重；非法码报错。
  4. 配方墙：浏览已收录配方；"按这配方来一杯" → 去吧台按预设参数出杯（M8）。
- **边界**：不做云同步/多人共享库（传播靠配方码）；不改 story/** 与 content/**；配方库为本机存储
  （库级导出/发布全体玩家 = 后续批）。
- **验收**：机检——① 提交码 round-trip；② 非法/篡改码拒绝；③ 去重；④ 配方墙读取。
  手工：编辑 → 提交 → 收录 → 按配方出杯全链。
- **依赖**：M8（参数 → 冲煮预设）。

### M8 冲煮交互：出杯手感

- **目标**：把"点一下出杯"升级为短而有手感的冲煮交互；永不成为新的卡点。
- **功能点**：
  1. 出杯流程插入交互环节（选豆选品之后、出杯判定之前），按饮品 method 映射技法：
     浓缩→压粉/萃取；手冲→分段注水节奏；奶咖→奶泡/融合；（未来）滴滤→注水流。
  2. 交互产出"这杯的手法评级"（好/一般/失误）→ 影响当日满意度与评价文案；**失败也出杯、不扣资源**；
     无操作超时自动完成（防卡死）。
  3. 单轮 ≤15 秒；触摸与鼠标均可；尊重 `prefers-reduced-motion`（静态降级）。
  4. 参数由豆/饮品数据派生（烘焙度→水温区间等），使 M7 配方预设可复现。
- **边界**：不做物理模拟、不做多轮进阶；不产生硬失败；不改经济数值栏。
- **验收**：机检——① 超时路径返回可出杯结果（防卡死）；② 三种 method 各有映射；③ 参数派生纯函数测试。
  手工：手机上完成一轮。
- **依赖**：M1（出杯主链路）、M3（日内循环）、M7（配方预设）。

### M9 全局导航：目录栏与返回置顶（2026-09-30 真机走查增补 · 批次 b03）

- **依据**：用户 2026-09-30 真机走查原话「每次能否有个目录栏，直接调回，每次调回，都在页面上端」；
  澄清：取界面层（全局导航），目标页从顶部开始显示（不保留上次滚动位置）。
- **目标**：玩家在任意界面都能一眼看到「回主界面 / 店内」的去路，一次点击直达、不用逐级点回；切换页面后总是从顶部开始看。
- **功能点**：
  1. 全局导航入口（目录栏）：任意界面（本身即首页 / 店内者除外）都可见统一的回程入口，一次点击直达「首页（主界面）」或「店内」；
     形态（顶部目录栏 / 悬浮入口 / 现有页头升级等）由设计定，须与现有视觉风格一致。
  2. 返回置顶：任何视图切换（含快捷入口与既有各条跳转）完成后，目标页面从顶部显示，不保留上次滚动位置。
  3. 覆盖清单：设计逐屏给出「视图 × 入口存在性 × 点击落点 × 置顶」对照表，兼作走查清单（以 `type View` 联合全部成员为准）。
- **边界**：不改 `story/**`、`content/**`；不新增业务页面、不改现有信息架构与各视图既有返回逻辑（叠加不替换）；
  不引入路由库或任何新依赖；桌面与移动同一套实现。
- **验收**（机检）：① 覆盖清单内每个视图均存在回程入口，且自该视图至「首页 / 店内」≤1 次点击（组件级断言）；
  ② 视图切换后滚动位置在顶部（断言点按设计核实的滚动承载面定：`window.scrollY` / 容器 `scrollTop`）；
  ③ 现有测试全绿 + `npm run build` 通过。手工（用户）：真机走查——任意界面回跳一次，确认落点与置顶。
- **依赖**：`game/src/nav.ts`（视图清单与契约——`type View` `:23`、导航落点 `navEntries` `:33`、屏幕键 `screenKeyOf` `:45`）；
  `game/src/App.tsx`（视图中枢——`useState` `:113`、滚动复位 `:172`、跳转助手 `openDesk` `:479`、页头 `:490`、视图分支 `:543-641`）；
  `game/src/styles.css`（页头吸顶 `.topbar-sticky` `:98`、`.topbar` `:101-110`、移动断点 `:820`）。

## 6. 风险与依赖

1. `App.tsx` 为 761 行单文件且本批多数功能要接入 → 设计需给出模块化方案（新功能独立文件 + 最小接线），
   避免在旧文件上叠补丁（工程纪律：遇到坏结构当场修，不叠补丁）。
2. M3 生成器与 M8 交互是新增"活"逻辑，必须与旧流程兼容（回归测试兜底）。
3. PWA 缓存与更新需版本化缓存名 + 新版本提示，避免"改了不生效"。
4. 手机真机实测只能由用户完成 → 交付时附走查清单。
