## 一、方案与理由

本批补 5 张书源卡，把新主线的七杯里的 5 杯接上书源，并挂到旧线第四章的 3 个关卡上。

- **书 2 → 新建分片** `content/knowledge/b2-b1-46.json`：knowledge-200（冰滴壶，器具）、knowledge-201（冷萃参数，冲煮）。
- **书 4 → 续号写既有分片** `content/knowledge/b4-p1-235.json`：knowledge-448（美式壶原理，器具）、knowledge-449（摩卡命名，产地）、knowledge-450（卡布奇诺时段，冲煮）。
- **挂接** `story/chapters/chapter-04.json`：3 个关卡的 `reward.unlock_knowledge[]` 各追加元素（只增不改，见 §4-D3）。
- **镜像与登记**：`content/关卡知识库对照.md` 同步、`contracts/CONTRACT.md` 变更记录加一行、`npm run kb` 重生成 HTML 生成物。

每杯 1 张（需求档 F1 允许每杯 1~3 张，总量以设计勘察为准）。理由：书源侧可用的独立知识窗口有限——书 2 只有「调配·浸泡法」一节含装置与参数两段，书 4 三杯各只有一处窗口；拆卡以「一卡一知识点」为界，不硬凑张数。

七杯覆盖：5 杯有卡（上表），黑糖拿铁与余温特调书源无对应内容 ⇒ 记缺口表（§6.4），不硬造卡（需求档 F1 边界）。

## 二、接口契约

数据面：知识卡 schema（`contracts/knowledge-card.schema.json`）。本批取值规则：

- **id 段**：书 2 → 2xx 段（`contracts/CONTRACT.md:44`），本批取 200、201；书 4 → 4xx 段（`contracts/CONTRACT.md:46`），续在既有最大号 447 之后取 448、449、450。
- **文件命名**：`content/knowledge/b<书号>-<分片>.json`（`contracts/CONTRACT.md:49`）；ID 段与文件名书号不符 = 校验 error（`contracts/CONTRACT.md:50`）。
- **title**：2~20 字。
- **category**：六枚举内取一（产地 / 咖啡豆 / 器具 / 冲煮 / 人物 / 故事线索）。
- **plain_explanation**：10~120 字白话。
- **source_book**：书 2 写作 `咖啡全书`，书 4 写作 `咖啡原來是這樣的啊`（与既有卡一致）。
- **source_chapter**：书 2 用「节名」形（如 `调配·浸泡法`），书 4 用「篇 章 节 小节名」形（如 `下篇 第三章 第一节 五、卫生委员：美式壶`）。
- **source_quote**：≤200 字，逐字摘录，可用 `……` 连接不相邻句（成例：对照.md 中 k-413 / k-415 / k-416）。
- **source_locator**：书 2 写 `b2 block.NN`（原文 block 标记），书 4 写 `p.<页码>`（`content/EXTRACTION.md:16`）。
- **confidence**：逐字核对无误 = `high`；含推断 = `medium` 且必带 `inference_note`（`content/EXTRACTION.md:61`；schema 强制，`contracts/knowledge-card.schema.json:57,69`）。
- **related_stages**：留空数组，由故事轨反向补（`contracts/CONTRACT.md:36`）。

挂接面：`story/chapters/chapter-04.json` 的 `reward.unlock_knowledge[]` 末尾追加 ID。

- 不改 `knowledge_brief[]`，不改 `choices[].knowledge_id`，不改任何剧情、逻辑、数值字段（§4-D3）。
- 追加后关卡头的镜像计数与对照.md 行同步递增（§3、§6.2）。

「八、当前项目的特别约束」口径（`story/WRITING_LOOP.md:200-214`；L212 禁改句：「不要修改可运行的 `story/chapters/*.json`」）：该条字面禁止修改 story 章节文件；本批按用户指令执行旧线挂接，处理口径 = **仅知识字段追加、零剧情/逻辑改动、不重排**。实现后的 `git diff` 白名单 = chapter-04.json 的 3 个 `unlock_knowledge` 行，其余行一律不得出现在 diff 中（V4 判法）。此约束与处理口径为评审重点（需求档 F2、现状锚点）。

## 四、关键决策记录

**D1 · 术语桥：卡面用游戏术语、摘录保原文、confidence=medium 加 inference_note（200 / 201）**

- 背景：书 2 全书只用「冷泡法」（无「冰滴 / 冷萃」字样，需求档现状锚点）；新主线杯名是「冰滴」「冷萃」。
- 决策：title 与 plain_explanation 用游戏术语（冰滴壶 / 冷萃）；source_quote 逐字保留「冷泡法」原文；confidence = `medium`，inference_note 写明桥接依据。
- 理由：卡是给玩家用的，须能对上杯名；摘录必须可逐字核（V3）；桥接属推断，medium 是如实标注。
- 被否：① 卡面写「冷泡法」——玩家按杯名找不到对齐对象；② 写 `high`——与摘录性质不符，V3 判不符。
- 影响：对照.md 的两条入档行加一行 `推断说明：` 子行（该文件此前无 medium 卡，体例扩一子行，见 §6.2）。

**D2 · 一卡一知识点，先切邻域角度再落卡**

- 200 × 201：同窗口分家——装置形态/原理归 200，数字（粉水比 / 时长 / 滴速）归 201，两卡不重叠。
- 448 × k-416（美式壶要粗粉多放，p.141）：448 只写「为什么是滴滤」的原理，操作细节归 416。
- 449 × k-245（摩卡壶配深烘豆）/ k-415（摩卡壶要大火）/ k-250（摩卡其实在也门）/ k-301（摩卡港与摩卡之名）：449 只写「摩卡」这名字的三处来路（港口 / 豆 / 壶），不写操作（415）、不与 250/301 重复地理史实；归类随同题卡 250 / 301 取「产地」。
- 450 × k-243（罗马的浓缩配豆，提到卡布奇诺）：450 只写饮用时段习俗，配豆内容归 243。
- 理由：挂点语义相符（V4）要求先切角度，否则同书邻域必然撞题。

**D3 · 挂接只走 `unlock_knowledge[]`，brief 与 choices 零改动**

- 理由：五张新卡都不是既有选项的判据（各关 choice 的解释文本与判据已定稿）；brief 是关内决策提示面，塞入非判据卡会让提示与选项脱钩。「过关入档」即可让玩家在知识库获得该卡，满足「可玩到」（F2 允许三形式任取）。
- 被否：① 同时进 brief（如 448 进 4-9）——提示面与判据面语义错位；② 用 `choices[].knowledge_id` 指向新卡——会改选项判定语义，属本批禁区。
- 后果：对照.md 新增行一律标「过关入档」；4-8「街对面的争吵」无相符卡 ⇒ 记缺口观察（§9）。

**D4 · `related_stages` 全部留空**

- 理由：契约明文允许留空、由故事轨反向补（`contracts/CONTRACT.md:36`）；既有 173 张卡均为空数组；挂接关系已由 chapter 侧表达，双写会造第二个事实源。
- 被否：回填关卡号（F3 允许，但与既有全部卡口径不一）。

**D5 · 号段与分片名取既有登记件，不新造口径**

- 书 2 分片名与号段直接采用 `content/EXTRACTION.md:35` 已登记的 E 行（`b2-b1-46.json` / knowledge-200~239），不另起名字。
- 450 比 `content/EXTRACTION.md:34` 的计划上限（400~449）多 1 号；以契约面为准（`contracts/CONTRACT.md:46`：书 4 = `4xx` 段，无上限），计划面非规范面 ⇒ 450 合法。该出入记 §9 观察项。
- 分片切号段按 `contracts/CONTRACT.md:52-53` 在变更记录登记一行。

**D6 · 对照.md 的同步口径（手工镜像）**

- 追加行体例照该关卡段落既有行：`- **卡标题**　\`knowledge-NNN\`　类别 · 可信度 X · 过关入档`，其后 4 行子行（讲什么 / 来源书籍 / 来源章节 / 原文依据）；medium 卡（200 / 201）在原文依据后另加一行 `推断说明：`。
- 关卡头「涉及知识卡 N 张」按该关新增去重卡数递增（4-5 +1、4-6 +2、4-9 +2），改后逐关复核与三处引用一致。
- 统计段（`content/关卡知识库对照.md:2255-2257`）：知识卡总数 173 → 178、已挂到关卡 173 → 178、没挂到任何关卡 0（不变）。
- 该文件无机器校验（手工同步）⇒ V5 靠逐字核对（§9 观察项）。

### 6.3 边界与错误案例

- **空白归一化**：两本书的原文含断行与行内空格（如「推 崇，」「！ 蓝山」），命中判法 = 去空白后逐字比对；`……` 可连接不相邻句（成例 k-413 / k-415 / k-416）。
- **不猜**：窗口内若出现错行 / 乱码 / 表格错位，该卡不写，停手上报，不自行扩大文件面；本批两段窗口已确认为可读正文（`content/raw/**` 不入库、不入 diff）。
- **错误①**：201 写成「冰滴专用」的归属断言 ⇒ 越界（原文同段口径），须为「冷泡时……」（§6.1）。

- **错误③**：chapter-04.json 的 diff 出现 `unlock_knowledge` 行以外的任何行 ⇒ 违 §八 处理口径（§2、V4）。
- **错误④**：对照.md 只加行、不改关卡头计数与统计段 ⇒ V5 判红。

## 九、发现与上抛

1. **V3 无机器校验**：摘录可核性靠 §6.3 的人工核法；是否做校验器扩展留给后续批次（本批不做）。
2. **对照.md 是手工镜像**：2262 行无生成脚本，本批手工同步（V5 逐字核）；若后续加卡频繁，可考虑生成器。
